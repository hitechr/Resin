# Optional IP Quality

Set `RESIN_IP_QUALITY_ENABLED=true` with a nonempty `RESIN_ADMIN_TOKEN` to enable admin-only IP reputation checks. The default One IP-compatible endpoint is `https://ip.huzhihui.com/api/ip/health`; set `RESIN_IP_QUALITY_ENDPOINT` to an operator-approved HTTPS endpoint to override it at startup. Confirm provider bulk-use terms and disclosure of the full egress-IP inventory before enabling automatic checks, especially with the public endpoint. A self-hosted One IP still depends on Net.Coffee upstream. Resin does not copy or bundle One IP's AGPL code; it consumes an HTTP contract. See the [One IP Worker](https://github.com/zhihui-hu/one-ip/blob/main/public/worker/ip-health.js) and [license](https://github.com/zhihui-hu/one-ip/blob/main/LICENSE).

The node-pool page groups the **filtered** nodes by normalized public egress IP; nodes with absent or non-public IPs appear in one labelled unresolved group. Each row shows the region (flag + code) agreed on by the majority of its matched nodes. `GET /api/v1/node-ip-groups` sorts the full filtered projection by risk/score/IP/node count/region before pagination. Unknown risk and the unresolved group sort last in either direction. `GET /api/v1/node-ip-groups/{ip}` and `/unresolved` return paginated matching nodes and cached quality only. All three GETs and opening the dialog send **no** provider request. Per-node detail/probe/check actions still use the node hash. A changed IP stops matching its previous IP group.

An admin can start `POST /api/v1/node-ip-batches` with the existing node filters in the query, then poll `GET /api/v1/node-ip-batches/{id}` or call `POST /api/v1/node-ip-batches/{id}/cancel`. The server snapshots all matching nodes regardless of visible page, deduplicates public IPs, and skips fresh cached entries. It rejects more than 1,000 distinct IPs in one job and rejects a full 10,000-IP queue rather than truncating work. The group list also reports current `queue_pending` and cumulative `background_deferred` IP attempts (queue overflow, departed IPs, or exhausted provider retries); deferred background work is rediscovered on a later refresh or midnight scan. Jobs report unique total, fresh skipped, completed, failed, deferred, canceled, timestamps and a sanitized error summary. Up to 128 recent job records are retained in memory; a restart or expiry returns `IP_QUALITY_JOB_NOT_FOUND`. Cancel drops queued work and cancels an active lookup when it has no other waiters; prior successful cache values remain.

Automatic inventory checks require a separate `RESIN_IP_QUALITY_AUTO_ENABLED=true` startup opt-in as well as `RESIN_IP_QUALITY_ENABLED=true` and a nonempty admin token; the automatic flag defaults to false. When enabled, a successful subscription apply enqueues its known public IPs; a first successful egress observation or a changed IP enqueues that public IP. Fetch/parse/stale-success failures, disabled nodes, region-only/circuit changes, failed probes and page reads enqueue nothing. A bounded event channel may defer subscription events under load; the next successful refresh or midnight scan rediscovers missing/stale IPs. Before each background provider request the current pool membership and IP are checked again. No new egress probe is started just for quality data.

Successes are kept in a bounded 10,000-IP in-memory LRU, fresh for 24 hours and then shown as stale until evicted; restart or changing the endpoint clears the cache. Unknown scores and flags are not zero or false. The score is third-party IP reputation (higher is better), not node availability or a routing signal. Disabled or unroutable nodes may have only a last observed IP. Provider failures do not alter node health.

Risk policy `v1` calculates `max(100 - score, floors for explicitly true flags)` in [0, 100], with Tor 90, abuser 85, proxy 70, VPN 60 and datacenter 45. When the score is null, risk remains null even when a flag is true; show known flags separately. These floors are provisional product assumptions pending labelled account-restriction samples, not One IP coefficients or a probability of account suspension. Risk is computed on read from cached quality, so revising the version does not require new provider requests.

The midnight scan uses the container's local timezone (`TZ`), at most once per local calendar day including DST transitions. Restarts do not catch up missed dates; the next daily scan waits until the following local midnight. A separately successful subscription refresh at startup can still enqueue its IPs. Quality and in-memory jobs are lost on restart. Actual distinct-IP count is not available in this repository; manual-batch limit 1,000 distinct IPs and queued-work cap 10,000 are provisional and require operational calibration. At one provider request per second, 1,000 uncached distinct IPs take at least about 17 minutes. None of these checks changes routing or node health.

Each process admits at most two in-flight lookups and one new request per second across manual and background checks. Failed provider requests are retried at most twice with bounded backoff; an invalid response is not retried. The public Worker documents a per-caller GET limit of 180 per 60 seconds, but offers no bulk-use or availability guarantee. Multiple Resin instances do not share a rate budget; coordinate a shared limit across replicas or use an authorized endpoint. No persistence migration or routing policy is included.
