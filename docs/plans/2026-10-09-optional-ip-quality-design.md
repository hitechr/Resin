# Optional IP Quality: Requirements and Design

Date: 2026-10-09. Status: design for a separate implementation session; no product code is changed by this document.

## Evidence and terminology

- One IP's `GET /api/ip/health?ip=<public-ip>` is implemented in `public/worker/ip-health.js`. It forwards to `ip.net.coffee/api/ip/lookup/<ip>`; `score` is upstream `trust_score` (0-100, higher is better), not a measurement performed by Resin. The Worker rejects upstream IP mismatches. Null scores and flags mean unknown, not zero/false. Its README states 75-100 good, 45-74 moderate, below 45 poor, and `unknown` for missing scores. The public Worker has a per-caller GET limit configured as 180/60 seconds, returns `no-store`, and has no published availability or bulk-use guarantee.
- One IP is AGPL-3.0-only; Resin is MIT. Integrate through a documented HTTP contract, without copying its source or bundling its UI. Third-party endpoint usage/terms must be confirmed before production use. An operator can instead explicitly configure an authorized self-hosted HTTPS endpoint.
- In this design, **IP quality** means third-party reputation of a public egress IP. It is not node availability, latency, routing health, streaming/AI access, or a guarantee against account restrictions. A **node** may share one egress IP with other nodes; a node can change IP between checks.
- Resin already exposes `egress_ip` in `internal/service/control_plane_platform.go`'s `NodeSummary`, authenticates `/api/v1/nodes` under the control plane, and renders a node detail drawer in `webui/src/features/nodes/NodesPage.tsx`. These are the owner boundaries for the first UI entry.

## Requirements

1. The feature is off by default. Enable only with `RESIN_IP_QUALITY_ENABLED=true`, a nonempty admin token, and an operator-approved One IP-compatible HTTPS endpoint. Default endpoint when enabled: `https://ip.huzhihui.com/api/ip/health`; allow `RESIN_IP_QUALITY_ENDPOINT` to override it at startup. No provider URL or arbitrary target IP is accepted from API clients. Document that the configured service receives the egress IP and that a self-hosted One IP still relies on Net.Coffee upstream.
2. Add a read-only **IP Quality** section to the existing node detail drawer only when enabled. Opening the drawer reads *local cached data only*; no third-party request. A clearly labelled **Check IP quality** command starts an on-demand lookup for that node's current public egress IP. Do not add automatic whole-pool scanning, list-column enrichment, or periodic quality probes in phase 1.
3. Show: nullable floating-point score (0-100, no rounding at storage), provider's derived status (`good`/`moderate`/`poor`/`unknown`), ISP, ASN, six nullable flags (`residential`, `datacenter`, `vpn`, `proxy`, `tor`, `abuser`), source (`One IP / Net.Coffee`), observed time, and fresh/stale state. Render `null` as Unknown, never as No/0. Explain the score direction in the label (higher is better). Do not mix this score with Resin's healthy/circuit-open badge. For a disabled or unroutable node, label its egress IP as last observed; the result describes that IP, not a current route.
4. Cache by normalized egress IP, not node hash. A successful lookup is fresh for 24h; an expired result may be shown as Stale until evicted, but is never refreshed by opening the drawer. Use a bounded 10,000-entry LRU in memory; cache is intentionally lost on restart. Nodes sharing an IP reuse the same result. A changed IP must never display the old IP's result for that node. Provider errors must not overwrite the last successful cached result.
5. Bound external work: at most two in-flight provider requests, one new request per second per Resin process, one 12s HTTP timeout, at most 64 KiB response, no redirects to other hosts, normalized response IP must match the requested IP. Validate score, enum and nullable flag types; reject malformed JSON and non-public IPs. Coalesce simultaneous requests for the same IP. The per-process rate is not a cluster-wide guarantee when multiple Resin instances share one public IP; operators must provision a shared budget or lower per-instance rates. Expose safe error codes (disabled, no/changed egress, rate limited, provider unavailable/invalid), never raw upstream bodies or credentials. No routing, allocation, probe failure counter or circuit state changes from these results.
6. The admin-only controls work when quality data is unknown, stale, provider down, rate limited, node disabled, or its egress IP changes. An admin-token-free deployment must reject enabling the feature at startup. Disabled deployments retain existing node/API behavior and send no quality requests.

## Technical design

- `internal/ipquality/`: typed One IP HTTP client and bounded in-memory cache/service. Use existing mature `golang.org/x/sync/singleflight` and `golang.org/x/time/rate`; for the LRU prefer the existing `github.com/golang/groupcache/lru` module (promote to direct dependency if used), protected by a mutex, with timestamps in values. Inject HTTP client and clock for tests. Do not call IP quality via the node outbound: this is an IP reputation lookup, not a per-node connectivity test.
- `internal/config/env.go`: parse opt-in flag and optional HTTPS endpoint; validate at startup, including nonempty admin token when enabled. Expose only `ip_quality_enabled` in the system env configuration response so the UI can hide the section. Endpoint changes require restart, which also resets the in-memory cache.
- Wire service at `cmd/resin/app_runtime.go:buildNetworkServers` into `service.ControlPlaneService`, not into topology/routing. Resolve node hash through the pool for both actions; compute the current public egress IP server-side. Return states from `GET /api/v1/nodes/{hash}/ip-quality`: `disabled`, `no_egress_ip`, `not_checked`, `fresh`, `stale`; include `egress_ip` and optional quality payload only for matching cached IP. `POST /api/v1/nodes/{hash}/actions/check-ip-quality` triggers a manual lookup, returns the same typed payload, and re-checks the node's current egress IP before reporting it. Cache the old IP result if the node changed, but respond with a changed-IP conflict instead of presenting it for the node. Both routes live behind existing admin middleware.
- UI (`webui/src/features/nodes/`): a separate small component for cached state, action/loading/error, score and flags in the existing detail drawer. Query key includes node hash *and current egress IP*; invalidate/refetch after checking. No background refetch of third-party data. Use a neutral Unknown state and distinguish Stale from provider failure; do not imply negative flags when null.
- Use a fixed result schema owned by Resin, not One IP's entire upstream JSON. Treat `score:null` as `unknown`, including if all flags are null. Provider's remote `checked_at` is not authoritative for local cache TTL: use a local observed timestamp. Provider 429 or outage leaves any previously successful result visible as stale where applicable; a rejected request yields a UI error and is never counted as a node probe failure.

## Acceptance and exclusions

- Disabled by default: existing node workflows unchanged; no external calls. Enabling without admin token fails validation. Only public current node IPs can be checked; manual check of two nodes sharing an IP coalesces to one provider call; IP changes never show mismatched results.
- A 200 response with `score:0`, `score:null`, `flags.proxy:false`, and `flags.tor:null` preserves all four distinctions in API and UI. A response naming a different IP is rejected. Timeout, 429, malformed JSON, 5xx, rate limit, and concurrency limit produce explicit bounded failures without marking the node unhealthy. 24h freshness boundary and LRU capacity are tested.
- No persistence migration, provider aggregation, provider credentials, bulk checks, automatic exclusion, score-based routing, historical charts, CDN/AI unlock, browser fingerprints, or DNS/mail checks in phase 1. Any later routing policy needs a separate owner decision and safety review.
